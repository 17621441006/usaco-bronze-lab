# USACO Lab · 铜组升银组

Bronze regular-season learning site. Silver, Gold and Platinum remain reserved headings. US Open is excluded.

## Scope and provenance

- 33 regular rounds, 99 Bronze problems: December 2015 through 2026 Contest 3.
- All 99 problems have sample-specific 3D/2D diagrams, independently authored Python 3 and C++17 reference programs, and complete official test files.
- The 1,156 official files range from 10 to 20 per problem. Original ZIP sources and SHA-256 hashes are recorded in each manifest. Large files are compressed and fetched one at a time on demand; none is omitted for size.
- All 99 problems have learning classifications across 13 topics, reviewed against the existing reference explanations. The 19 pre-existing official-review records remain separate. Practice stages are teaching guidance, not official difficulty ratings. Optional DP is explicitly distinguished from the basic route.
- The user supplied a complete bilingual HTML/PDF anthology. Its 78 actual problem entries contain 60 regular-contest problems and 18 US Open problems. Only the 60 regular problems (2020–2026, 20 rounds) are bundled here, preserving the requested scope. The anthology’s cover count is not used as the catalog source of truth. The 39 earlier problems remain searchable and categorized with their existing original-source reader.
- Statements and teaching classifications updated 2026-10-04. No automatic synchronization is enabled.

## Learning and evaluation

The 60 recent problems open directly from `data/local-statements.json`, defaulting to full English text. Chinese switches immediately to the supplied full translation: 42 are marked official in the anthology and 18 retain the nonofficial translation label. Body text, constraints, scoring, sample explanations, credits, LaTeX and sample code blocks are preserved. Four image occurrences share two local PNG assets. No USACO iframe, external translation service or third-party math script is used for these 60 statements. KaTeX and its fonts are bundled. Fullscreen reading and optional source links remain available; Summary stays inside the help tab. The already complete inline samples are not repeated beneath the local statement.

The 39 earlier statements retain their existing official reader (or a previously saved local document). `data/statement-sources.json` retains the original URLs checked on 2026-10-03. No new full statements were fetched from the web for this update.

The archive defaults to 2020-and-later regular contests, newest first. Knowledge mode exposes all 13 categories with recent and all-year counts, prerequisite links, year/stage filters and an optional foundation-to-challenge order. Classic and all-year tabs retain the earlier content. Text searches cover all years and reset narrower topic/year/stage filters. Round mode groups complete three-problem papers, omits topic spoilers, and links to the corresponding timed-practice setup. Open archive tabs preserve filters when navigating elsewhere. The pathway preview now uses the 2024 Cheese Block example.

The initial workspace is reading-only: the 192-pixel navigation is expanded by default (new v2 preference, so the earlier collapsed default is not reused) and the editor is lazy-loaded after Start coding. Students can switch between reading, split view with a draggable divider, and focused coding. Page tabs have separate title and close-button styles, a 145-pixel minimum width and an overflow strip; titles no longer inherit the 24-pixel close control. Closable page tabs retain each open problem workspace, drafts and reading state. Closing a tab preserves saved code and notes, but resets its reading layout when reopened. Samples are expanded on the original tab. Summary and topic tags appear only after entering the learning guide; that guide and the reference-code tab show their contents directly. Layered hints remain opt-in.

The student-facing statement-import action remains removed. Imported build-time documents take precedence, while previous device-local statements remain stored and are used for older problems. Runtime documents are sanitized; the import script separately strips active markup and extracts embedded images to same-origin assets. `data/statement-import-report.json` records the supplied file hash, per-language source hashes, exclusions and translation provenance.

Each problem uses its own first official sample for its data diagram. Multi-test examples focus on their first scenario and say so. Sample diagrams retain rotation/zoom and SVG alternatives; algorithm classrooms use drag rotation while the wheel scrolls the page. All 18 algorithm lessons have an actor-based 3D scene and a 2D alternative, with task, units, current action and state values. New scenes use real semantic objects (milk buckets, breed groups, cattle queues, feed bags, pasture areas and connected barns); existing cheese, reflection, printing, MOO, arrays, binary-search and stair-DP scenes now explain FJ/Bessie roles. These are functional teaching models, not decorative illustrations. Dedicated adjustable models remain available for Fence Painting, cheese removal, Moo Hunt and selected algorithm lessons.

Reference panels contain the approach, complexity, both complete programs, copy/download controls and local validation records. Python and C++ solutions were checked against all official files. Cow Checkups (1469) has an explicit Python performance warning: all outputs were checked using a longer 60-second local budget after five large files exceeded the initial eight-second budget. This is not a claim of passing the official Python time limit. C++ passed its local four-second-per-file verification for every problem.

The IDEA-inspired Monaco workspace includes a project tree that is collapsed by default, file tabs, new Python/C++/text files, a selectable entry point, read-only sample files and a results console. Existing single-file drafts migrate into main.py and main.cpp without overwriting their content. Closing a file tab does not delete its contents. Python can import project modules; local modules and files reset between test cases to prevent state from leaking across cases. Monaco provides Python/C++ editing and local completion providers: Python built-ins (including pr → print()), loop/function snippets, container methods, common standard-library members, file-defined names and C++ templates. Tab/Enter accepts suggestions and Ctrl+Space opens them manually. These are curated completions, not a Python type-checking language server. Monaco assets and license notices are copied from the pinned package into public/editor by scripts/prepare-editor.mjs for both development and production; the editor no longer loads its resources from the default external CDN. Python executes via Pyodide 0.27.7 in a disposable browser worker. Full-data evaluation reports AC, WA, RE and **local-limit TLE** per file. Initialization and file-download time are excluded from the per-file limit. On timeout the worker is terminated and recreated for the next file. Output comparison uses the complete output before shortening the display. Historical file input/output and buffered standard I/O are supported.

Constructive answers have semantic validators for Feeding the Cows (1252), COW Splits (1540), It's Mooin' Time IV (1563), and Swap to Win (1589); Word Processor checks line boundaries. Other problems use token comparison. Runtime judgments are local practice results, not official scores. C++ execution in the website is still unavailable; C++ references can be downloaded and run locally.

The sidebar now groups Learning (pathway → Python foundations → algorithms), Training and review (archive → timed practice → review), and Sources. There is no standalone workspace navigation item: IDEs open from a specific problem or exercise. The 192-pixel navigation remains expanded by default, with the exact official homepage wordmark and a clearly separate unofficial LAB label.

Python foundations contain eight sequenced lessons: I/O, integer arithmetic, conditions, lists, loops, strings, sets/dictionaries, and functions/iterator input. Eighteen algorithm lessons are grouped into six foundation methods, six reasoning/topics chapters, four recent-problem models and two bridge chapters. New chapters cover complexity/boundaries, direct simulation, enumeration, sorting, contribution counting, Ad Hoc/casework/invariants/construction, greedy proof/counterexamples, rectangle geometry, prefix/difference arrays, recursive search and graph reachability. Six new Python topics have step-by-step 2D execution diagrams; lists and loops use the existing 3D scenes. Each of the 26 lessons has three original coding exercises of increasing difficulty (78 exercises, 283 test cases). Samples are visible, coding opens on demand, and the normal Python runner evaluates the complete inline test set. Running samples or failing full checks does not mark completion. All three full checks must succeed before the lesson is complete. Exercise drafts and passed status have separate device-local keys, and old prediction-only checkpoints are not presented as completed courses.

All 99 Python references have statically unused imports and I/S helpers removed (777 imported names, 65 helpers). The four-line Fence Painting teaching version uses input(); its download preserves the historical paint.in/paint.out adapter. Other programs keep only their required imports and input adapters. Existing full-data correctness records are preserved. After cleanup, all 125 reference samples, the short fence solution on all ten official files, and all 283 course cases passed independent local execution (`scripts/verify-learning-content.py`). This regression check does not re-certify official performance limits.

Editor controls now include light/dark themes, a 12–28 px font size, manual Save and Ctrl/Cmd+S alongside automatic device-local saving, a full-screen writing view with Escape, and a pointer/keyboard height divider. The existing split-view divider adjusts the left/right share. Theme, font size and height persist locally. Only the exact old generated starter comments are removed from drafts; user comments and code are retained. Long hint content uses a definite-height, scrollable panel; newly expanded hints scroll into view, and wheel/touch scrolling can propagate at the panel boundary.

The completion vocabulary is generated from Python built-ins and common standard libraries, with curated snippets taking precedence. It includes 83 global callable names, 101 container/numeric/file methods and module-specific entries, including iter, next, int.bit_count, itertools and import aliases. The audit scans every call in all 99 references and all 78 exercise solutions; there are no missing function/member names. This is contextual completion, not type inference or static error analysis.

Drafts, notes, course progress and practice history are device-local. Timed practice uses a four-hour training timer and is not a secure or official contest assessment.

## Refreshing and validation

Use the existing npm scripts and Sites build workflow. Importers use Python standard libraries and curl:

```
python scripts/import-usaco.py
python scripts/curate-catalog.py
python scripts/import-full-tests.py
python scripts/author-diagrams.py
python scripts/sync-learning-assets.py
python scripts/classify-learning-topics.py
```

The manifest lists 33 known rounds. Add newly released regular rounds only after checking the official results page, then author and review solutions, diagrams and validators. Run `sync-learning-assets.py` after refreshing catalog metadata to restore full-data coverage. Do not count an optional editorial technique as a mandatory topic.

To re-import this supplied anthology, run `python scripts/import-provided-statements.py /absolute/path/to/anthology.html` followed by `python scripts/classify-learning-topics.py`. Both scripts stop on mismatched titles, incomplete language pairs, changed text, missing embedded images or incomplete catalog coverage. New rounds require updating these explicit expected scopes and authoring classifications rather than silently inheriting guesses.

`node scripts/verify-statement-import.cjs /absolute/path/to/anthology.html` verifies all 120 language bodies against the supplied document, 344 sample input/output occurrences against the existing catalog, all four local image occurrences, and 2,821 rendered formulas without KaTeX errors. Workspace DOM checks verify recent/classic/all counts, cross-year search, optional-DP classification, topic links, complete round groups, matching timed setup, persistent archive filters, immediate English content on first render, local Chinese switching, nonofficial labels, full-screen reading and no duplicate sample section. These are DOM checks, not actual browser visual inspection.

Reference sources live under `reference-solutions`; `scripts/verify-solutions.py [ids...]` compiles C++ and checks both languages against official data. It uses an eight-second Python and four-second C++ local budget by default; preserve and explain the separate Cow Checkups extended correctness verification. `data/reference-verification.json` records aggregate coverage, not official time-limit certification.

The browser worker and evaluation engine were exercised with real Pyodide through a Node worker adapter: ten official Fence Painting files, gzip loading, multi-file imports, helper-file traceback, independent module state for successive cases, historical and buffered I/O, correct/wrong output, exceptions, normal exits, unscored custom input, long output, and a forced infinite-loop timeout followed by a successful next case. All official expected outputs for the four semantic validators and the line checker were accepted; malformed, invalid and alternative valid constructions were tested. Reproduce with `PYODIDE_TEST_DIR=/path/to/pyodide node scripts/verify-browser-runner.cjs`.

Completion checks in `scripts/verify-completions.cjs` verify replacement ranges, the print snippet, module/member suggestions, file-defined names and idempotent provider registration.

DOM interaction checks in `scripts/verify-workspace.cjs` exercise expanded navigation and collapsed project-tree defaults, title-versus-close-button CSS, reading-first defaults, expanded samples, opening the IDE, Python/C++ file switching, file creation/close/reopen, read-only sample files, project-tree folding, page-tab state retention, old-draft migration, document sanitization and offline Chinese switching. These use jsdom with Monaco and 3D rendering replaced by inert test controls; they do not constitute browser visual inspection. Install jsdom outside the project as described in the script.

The current DOM checks also exercise editor themes, font size, vertical resizing, full-screen Escape, manual save, removal of only the generated comment, the hint scroll container, the 8/18 course split, progressive exercise switching, and completion gating. Their course runner is mocked to check UI wiring; real execution is separately verified by the native Python content checks and real Pyodide iterator/bit-count cases.

TypeScript and the production build are checked before publication. Browser visual inspection was not available in this environment.

## 2026-10-04 UI and curriculum audit

The visual system uses navy headings/selected lesson rows, copper primary actions and teal completion feedback on pale-blue working surfaces. Course groups, title accents and solid selected states make the hierarchy visible; normal teaching text is 16 px, controls 14 px. Responsive course navigation wraps into grouped rows on narrow screens. IDE dark and light controls retain their own accessible colors.

The original source logo is `https://usaco.org/current/images/usaco_logo.png`, linked by the official homepage. It is copied without alteration to `public/brand/usaco-logo.png`; source dimensions are 900×130. The site remains labelled as an unofficial learning platform. No claim of endorsement or logo ownership is made.

Curriculum evidence was rechecked against the authors' own directory at https://usaco.guide/bronze and https://usaco.guide/bronze/ad-hoc, and the official Walking Home (December 2021), Printing Sequences (February 2025), and Moo Hunt (2026 Contest 2) editorials. The Guide explicitly does not claim an exhaustive syllabus. Walking Home's official casework/enumeration route is now the primary learning classification; DP is optional. The course list is a teaching pathway, never a guarantee that all future Bronze problems fit a fixed algorithm checklist. Ad Hoc labels are cross-cutting reasoning tags reviewed individually; they are not assigned wholesale to every problem.

Fence Painting's interactive interval view now compares a 1D unit-segment marking array with the constant-space overlap formula. Both independently written Python and C++ variants use standard I/O, include assumptions/complexity, and passed all ten official data files (40 method/language/file checks). Sliders and step controls update marking cells; overlap remains 1. `node scripts/verify-teaching-scenes.cjs` checks 44 new 2D frame renders plus milk conservation, stable cattle identity, reachability, sorting and interval edge cases. It is a semantic/SSR check, not real WebGL rendering. `python scripts/extend-curriculum-exercises.py` reproducibly authors the 33 new original exercises without modifying earlier exercise IDs or progress keys.
